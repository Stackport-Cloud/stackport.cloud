<section class="quickstart" id="quickstart">
  <h2>Up and running in a minute</h2>
  <p class="subtitle">Start the emulator you use, then point StackPort at it. Open <strong>http://localhost:8080</strong>.</p>

  <EmulatorQuickstart />

  <p class="quickstart-footer">
    Prefer Docker Compose? Each guide has a file that runs the emulator and StackPort together, with a seed that creates demo resources.
    Already have an emulator running elsewhere? <a href="/docs/configuration/emulators/">Any AWS-compatible endpoint works.</a>
  </p>

<section class="features">
  <h2>What you get</h2>
  <p class="subtitle">Everything runs locally, talks the standard AWS API, and needs no setup inside your emulator</p>

  <div class="features-grid">
    <div class="feature-card">
      <div class="icon">📊</div>
      <h3>35 services, one dashboard</h3>
      <p>Every service probed in parallel, with resource counts that update live over a WebSocket. Star the ones you use and they move to the top.</p>
    </div>
    <div class="feature-card">
      <div class="icon">🧭</div>
      <h3>13 dedicated views</h3>
      <p>S3, DynamoDB, Lambda, SQS, SNS, EC2, IAM, RDS, KMS, Step Functions, CloudWatch Logs and Metrics, and Secrets Manager. Everything else gets a searchable table with JSON details.</p>
    </div>
    <div class="feature-card">
      <div class="icon">🎓</div>
      <h3>Guided lessons</h3>
      <p>Learn AWS hands-on without an AWS account or a bill. Lessons run inside the console and check your real resources, so a step turns green when the thing exists.</p>
    </div>
    <div class="feature-card">
      <div class="icon">✏️</div>
      <h3>Make changes, not just look</h3>
      <p>Upload to S3, edit DynamoDB items, send SQS messages, publish to SNS, invoke Lambda, start Step Functions executions, tail logs live.</p>
    </div>
    <div class="feature-card">
      <div class="icon">🔒</div>
      <h3>Real AWS, read-only when you want</h3>
      <p>Browse an account through your profile, SSO or keys. Set <code>STACKPORT_ALLOW_WRITES=false</code> and the server refuses every write.</p>
    </div>
    <div class="feature-card">
      <div class="icon">🔀</div>
      <h3>Many endpoints at once</h3>
      <p>Register emulators and accounts side by side, each with its own region and credentials, and switch from the top bar.</p>
    </div>
    <div class="feature-card">
      <div class="icon">💻</div>
      <h3>A CLI for scripts and CI</h3>
      <p><code>stackport status</code>, <code>list</code>, <code>describe</code> and <code>export</code> with table, JSON or CSV output. A VS Code extension is in early development.</p>
    </div>
    <div class="feature-card">
      <div class="icon">🐳</div>
      <h3>One Docker image</h3>
      <p>UI and API in a single container for amd64 and arm64, or a plain <code>pip install</code>. Configured entirely with environment variables.</p>
    </div>
    <div class="feature-card">
      <div class="icon">⌨️</div>
      <h3>Built for daily use</h3>
      <p>Keyboard shortcuts, deep links to any resource, JSON and CSV export, and light and dark themes. Press <code>?</code> to see the shortcuts.</p>
    </div>
  </div>
</section>

<section class="learn-highlight">
  <div class="learn-text">
    <h2>Learn AWS without an AWS account</h2>
    <p>
      Guided lessons run inside StackPort against your own emulator, so there is no account to create and no bill to worry about. A panel walks you through each step while markers point at the real controls.
    </p>
    <ul>
      <li>Do each step in the console or with the AWS CLI, with commands already filled in.</li>
      <li>StackPort checks the live state, so a step turns green when the resource really exists.</li>
      <li>Skip anything, come back later. Nothing is a gate.</li>
    </ul>
    <a href="/docs/learn/guided-lessons/" class="learn-link">How guided lessons work</a>
